## 1. The five design decisions that settle the rejected v0.1's blockers

### D1 — Identity is a source-scoped business key; `source_id` is lineage only

Every fact row carries a `natural_key` (constructed at ingest from the
source-scoped business identity: src × account × metric × date × ordinal, or
src × account × date × ordinal × amount-shape for events) and a `batch_id`.
The UNIQUE key is `UNIQUE(natural_key, batch_id)`:

- **B1 fixed:** `source_id` is out of the *identity* (it remains lineage), but
  the storage key stays source-scoped so two sources can legitimately carry the
  same business fact (competing evidence, copy-forward seams). Exact
  cross-source duplicates are blocked on the state side by `content_hash
  UNIQUE` (state hashes cover the value, so legit same-day pairs with different
  values never collide); on the event side by the per-source `dedupe_rule`
  applied at ingest (see D3), with suppression evidenced in `dedupe_log`.
- **B3 fixed:** re-ingest of the same source lands as new `batch_id` rows —
  append-only, no IntegrityError aborts, no silent splice, no destroyed rows.
- **B4 fixed:** `seq_in_date` (derived ordinal) is carried *beside*
  `sheet_row_number` (raw, verifiable), and `src_tab.row_order`
  (`ascending-date | descending-date | unsorted`) is declared so "last row of
  the day" is never silently inverted.
- **B7 fixed:** the source's own durable id is kept as `business_txn_id` on
  events (the survey proved it exists and is collision-free for the disjoint
  family).

### D2 — State resolution is declared source precedence, not `MAX(seq)` across sources

`src_ref.precedence` (lower = more authoritative; curated per corpus: canonical
file outranks its older cut), then `sheet_modified DESC`, then `batch_id DESC`,
then `seq_in_date DESC` (the ratified "last event of the day wins", now applied
*within* one source), then `source_id DESC` as a deterministic tiebreak.
`v_state_current` exposes `source_id, batch_id, seq_in_date, ingested_at,
value_text` so any pick is auditable. `superseded_by_batch_id` marks rows a
newer load of the same source replaced; the view reads only
`superseded_by_batch_id IS NULL`. Same-day multi-event state rows (the TIPS
pair) survive in storage — only the *current-state* pick is single-valued, and
the pair is linked by `event_group_id` so its delta (contribution/dividend) is
derivable and auditable.

### D3 — The allow-list is data, complete with its negative half

`src_ref` (one row per source, `alias UNIQUE`) + `src_tab` (per tab/block:
`role` over the FULL vocabulary incl. `derived|scratch|worksheet|duplicate|
deferred`, `header_state` ∈ {confirmed, unresolved, not-applicable} with a
CHECK that confirmed ⇒ positive integer `header_row`, `dedupe_rule`, `grain`,
`row_order`) + `src_column` (col index → account/metric/unit map, with
`header_occurrence` for the ×4-repeated-label case). `data_defects` and
`coverage_calendar` FK to `src_ref.alias`.

### D4 — Presence is a property of the load, not of NULL

`fact_state` requires exactly one of `value_num`/`value_text`
(`presence ∈ {measured, estimated, error}`); absence lives in
`coverage_calendar.status ∈ {not-loaded, loaded-empty, absent-in-source,
loaded}` — the three states the survey said two booleans couldn't hold. All
REALs carry `typeof() CHECK`s; all dates carry the verified strict form
(`GLOB 'YYYY-MM-DD' AND date(x) IS NOT NULL` — the form leg 2 proved rejects
`4/31/2020`, `5/3/2025`, and serials).

### D5 — One enforcement posture: fail closed, fail loud

- No permissive defaults on classification columns (`entity`, `registration`,
  `purpose`, `is_flow`, `is_year_relative`, `is_estimate` all NOT NULL with
  CHECKs and no silent default); unmapped vocabulary lands as an explicit
  `UNMAPPED` sentinel per source, never NULL.
- `is_informational` exists once, on `dim_txn_type`; `v_cash_flow` is the
  published definition of "money that counts".
- `_schema_meta(schema_version='v0.2')`; the DDL applies to a **fresh store
  only** (no `IF NOT EXISTS` — re-application fails loudly; rebuild-from-Drive
  is the migration path), and the loader asserts version + `foreign_keys` on
  connect.

Grain handling: `period_grain` CHECK over a curated set

"mixed monthly to weekly" without pretending the enum covers them).

## 3. Ingest implications (toolkit changes, after panel pass)

1. Loader constructs `natural_key` per family from the `src_column` map;
   sets `batch_id` from a new `load_batch` row; wraps the batch in one
   transaction (mid-batch failure ⇒ rollback + `status='failed'` row).
2. Applies `src_tab.dedupe_rule`: `disjoint_by_key` (no dedupe), 
   `natural_key_prefer_latest` (mark prior rows `superseded_by_batch_id`,
   log to `dedupe_log`), `copy_forward_seams` (never merge year-relative
   columns across sources — absolute columns dedupe by key).
3. Normalizes raw labels (trim/case) before the `dim_txn_type`/`dim_category`
   lookup; unmatched labels create the `UNMAPPED` row, not NULL.
4. Strict date coercion with `raw_date_text` retention in the load log for any
   cell that needed coercing.
